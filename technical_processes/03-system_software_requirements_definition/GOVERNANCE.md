# Governance — System/Software Requirements Definition

## Methodology

This process follows **IEEE 29148:2018 — Systems and software engineering — Requirements engineering**.

Functional requirements are derived from acceptance criteria in the detailed layer.

## High Level Format

Human states: any additional non-functional requirements not covered by stakeholder stories or acceptance criteria.

## Detailed Format

Formal "shall" statements with source traceability:

```
SR-{nn}: The system shall [requirement].
Source: AC-{xx.y} | C-{nn} | A-{nn}
```

## Categories (from IEEE 29148)

- **Functional** — what the system does
- **Non-functional** — performance, usability
- **Data** — schemas, file formats
